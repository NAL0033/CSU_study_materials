# 参考电路 CPU.circ 模块详解——从零看懂单周期处理器

---

## 第 0 章：准备工作——怎么看懂电路

### 0.1 打开电路

1. 打开 Logisim（`D:\MyFiles\Downloads\logisim-win-2.7.1.exe`，需安装 Java）
2. `File → Open` 选择 `CPU.circ`
3. 左侧面板会显示所有子电路列表，点击可切换查看

### 0.2 Logisim 中三种最基本的元件

在 XML 文件中，每种元件都对应一个 `<comp>` 标签。你只需要认识三种：

| XML 标签 `lib` 值 | Logisim 中的名字 | 用途 |
|:---:|---|---|
| `lib="0"` | **Wiring（连线类）** | Pin（引脚/端口）、Splitter（拆分器）、Tunnel（隧道）、Constant（常量）、Probe（探针） |
| `lib="1"` | **Gates（门电路）** | AND / OR / NOT 门 |
| `lib="2"` | **Plexers（选择器）** | Multiplexer（多路选择器，MUX） |
| `lib="3"` | **Arithmetic（运算器）** | Adder（加法器）、Subtractor（减法器） |
| `lib="4"` | **Memory（存储器）** | Register（寄存器）、ROM、RAM |

### 0.3 怎么读懂连线

XML 中每条 `<wire from="(x1,y1)" to="(x2,y2)"/>` 代表一条**连线**（就是 Logisim 里绿色的线）。

- 坐标只是位置，不用深究
- **核心方法**：找到一个 Pin（引脚），顺着连线追踪信号流向，看它经过了哪些元件，最终到达哪个输出 Pin

### 0.4 输入和输出的读法

```xml
<!-- 输入引脚：tristate="false" 或没有 output 属性 -->
<comp lib="0" name="Pin">
  <a name="width" val="16"/>        <!-- 位宽 16 -->
  <a name="label" val="in"/>        <!-- 标签叫 "in" -->
</comp>

<!-- 输出引脚：output="true" -->
<comp lib="0" name="Pin">
  <a name="facing" val="west"/>     <!-- 朝向 -->
  <a name="output" val="true"/>     <!-- 是输出 -->
  <a name="width" val="32"/>        <!-- 位宽 32 -->
  <a name="label" val="out"/>       <!-- 标签叫 "out" -->
</comp>
```

**规则**：`output="true"` 的 Pin 是输出，没有的就是输入。

现在我们从最简单的模块开始。

## 第 1 章：Zero_EXT——16位→32位零扩展（最简单，仅 3 个元件）

### 1.1 功能

将 16 位输入**高位补 0**扩展成 32 位输出。

例如：输入 `0x1234` → 输出 `0x00001234`

### 1.2 用在哪里

`ori`（或立即数）和 `lui`（加载高位立即数）指令需要把 16 位立即数扩展成 32 位才能送入 ALU 运算。这些指令要求**无符号/零扩展**。

### 1.3 电路结构

```
输入Pin(in,16位) ────→ Bit Extender ────→ 输出Pin(out,32位)
```

只用了 **3 个元件**：

| 元件 | 类型 | 说明 |
|------|------|------|
| `Pin "in"` | 输入引脚 | 位宽 16，接收指令的低 16 位立即数 |
| `Bit Extender` | 位扩展器 | `in_width=16, out_width=32`，扩展模式默认零扩展 |
| `Pin "out"` | 输出引脚 | 位宽 32，输出扩展后的 32 位数 |

### 1.4 如何在 Logisim 中查看

1. 左侧双击 `Zero_EXT` 进入该子电路
2. 你会看到：左边一个 16 位输入，中间一个 Bit Extender，右边一个 32 位输出
3. Bit Extender 的配置：输入位宽 16，输出位宽 32，扩展类型为**零扩展**（Zero Extension）

### 1.5 关键知识点：什么是 Bit Extender？

Bit Extender 是 Logisim 内置的位宽转换元件。它有两种模式：

- **零扩展（Zero Extend）**：高位统统补 0
- **符号扩展（Sign Extend）**：高位全部填输入的最高位（即符号位）

> **为什么需要扩展？** CPU 的数据通路是 32 位的，但立即数只有 16 位，必须扩展成 32 位才能参与运算。

## 第 2 章：EXT——16位→32位符号扩展（Zero_EXT 的孪生兄弟）

### 2.1 功能

将 16 位输入**符号扩展**成 32 位输出。

例如：输入 `0x7FFF` → 输出 `0x00007FFF`（正数，高位补 0）
例如：输入 `0xFFFF` → 输出 `0xFFFFFFFF`（负数，高位补 1）

### 2.2 用在哪里

`lw`、`sw`、`beq` 指令中的立即数（地址偏移量）是有符号的，可能在负方向偏移，所以必须**符号扩展**。比如 `lw $t0, -4($sp)` 中的 `-4` 用 16 位表示为 `0xFFFC`，符号扩展到 32 位后为 `0xFFFFFFFC`（即 -4）。

### 2.3 电路结构

```
输入Pin(in,16位) ────→ Bit Extender(sign) ────→ 输出Pin(out,32位)
```

| 元件 | 说明 |
|------|------|
| Pin `"in"` | 16 位输入 |
| **Bit Extender (sign)** | `in_width=16, out_width=32, type=sign` |
| Pin `"out"` | 32 位输出 |

### 2.4 Zero_EXT vs EXT 的区别

| 对比 | Zero_EXT | EXT |
|------|----------|-----|
| 扩展方式 | **零扩展**（高位补0） | **符号扩展**（高位填符号位） |
| 适用指令 | ori, lui | lw, sw, beq |
| 为何不同 | 逻辑运算不需要符号 | 地址偏移有正负方向 |
| XML 区别 | 无 `type` 属性 | `<a name="type" val="sign"/>` |

**如何看懂这个区别**：对比两个模块的 XML，Zero_EXT 的 Bit Extender 没有 `type` 属性（默认零扩展），而 EXT 的 Bit Extender 有 `<a name="type" val="sign"/>`。

> **一句话理解**：你手里只有 16 位数字，但 CPU 要用 32 位。如果是地址偏移（有正负），就用符号扩展；如果是逻辑运算操作数（无符号），就用零扩展。

## 第 3 章：Shift——32位数左移2位

### 3.1 功能

将 32 位数左移 2 位（等价于 ×4）。

例如：`0x0000_0100` → `0x0000_0400`

### 3.2 用在哪里

`beq` 分支指令。beq 的 16 位偏移量是以**指令字**（4 字节）为单位的，需要 ×4 才能得到字节地址。符号扩展后还需要左移 2 位。

### 3.3 电路结构

```
32位输入 ──→ Splitter(拆分) ──→ [高16位? 低16位重组] ──→ 32位输出
                                   ↑
                              Constant(0x0) ─→ 最低2位填0
```

| 元件 | 说明 |
|------|------|
| Pin（输入） | 32 位输入 |
| **Constant 0x0** | 一个值为 0 的常量 |
| 两个 Splitter | 拆分和重组合数据线 |
| Pin（输出） | 32 位输出，左移 2 位 |

### 3.4 实现原理

1. 用一个 Constant(0) 提供 2 位 0
2. 输入 32 位通过 Splitter 拆开
3. 重组时：原高 30 位向高位移动 2 位，低 2 位填入 0
4. 效果 = 逻辑左移 2 位 = ×4

> **简化理解**：在二进制中，末尾加两个 0 就是 ×4，就像十进制末尾加两个 0 是 ×100 一样。

## 第 4 章：IM（指令存储器）——存放程序

### 4.1 功能

只读存储器（ROM），存放你的机器码程序。给定 5 位地址，输出 32 位指令。

### 4.2 电路结构

```
输入Pin(A,5位地址) ────→ ROM(32×32) ────→ 输出Pin(RD,32位指令)
```

| 元件 | 说明 |
|------|------|
| Pin `"A"` | 5 位地址输入（来自 PC） |
| **ROM** | `addrWidth=5, dataWidth=32`，存放机器码 |
| Pin `"RD"` | 32 位指令输出 |

### 4.3 ROM 里面存了什么

从 XML 可以看到 ROM 的内容：

```
3408006f 34090001 01094021 350a000c 012a4021 340b03e8 34e7ffff 3c050064
34050457 00000000 016a5821 014a5021 114b0009 ad490000 8d4f0000 8d570000
01e57823 00004821 ad2f0004 8d300004 01405821 116afff4 01495021
```

这些都是 16 进制机器码。例如：
- `3408006f` = `ori $t0, $zero, 0x006f`（给 $t0 赋值 111）
- `00000000` = `nop`（空指令）

### 4.4 工作原理

- PC（程序计数器）给出当前指令地址
- ROM 根据地址查出对应的 32 位机器码
- 机器码被送到译码阶段，拆分成 opcode、rs、rt、rd、func、imm 等字段

> **类比**：IM 就像一个数组 `IM[addr] = 指令`，输入地址就输出对应的指令。

## 第 5 章：DM（数据存储器）——存放运行时数据

### 5.1 功能

读写存储器（RAM），`lw` 从里面读数据，`sw` 往里面写数据。

### 5.2 电路结构

```
地址A(5位) ────→┐
写数据WD(32位)─→├──→ RAM(bus=separate) ──→ 输出RD(32位)
MemRead ──────→│
MemWrite ─────→┘
CLK ──────────→
```

| 元件 | 说明 |
|------|------|
| Pin `"A"` | 5 位地址（来自 ALU 结果） |
| Pin `"WD"` | 32 位写数据（来自 GRF 的 RD2，即要存的数据） |
| Pin `"MemRead"` | 读使能信号 |
| Pin `"MemWrite"` | 写使能信号 |
| Pin `"CLK"` | 时钟 |
| **RAM** | `addrWidth=5, dataWidth=32, bus=separate` |
| Pin `"RD"` | 32 位读数据输出 |

### 5.3 bus="separate" 的含义

RAM 有两种工作模式：
- `bus=separate`：读写数据线分开（WD 写入，RD 读出）
- `bus=shared`：读写共用一根数据线

这里选 separate，因为 lw 和 sw 的数据流向不同。

### 5.4 两种指令的行为

| 指令 | MemRead | MemWrite | 行为 |
|------|:------:|:--------:|------|
| `lw` | 1 | 0 | 读：RAM[A] → RD |
| `sw` | 0 | 1 | 写：WD → RAM[A] |
| 其他 | 0 | 0 | 不操作 RAM |

> **一句话理解**：DM 就像 `int DataMemory[32]` 数组，lw 是取数 DataMemory[addr]，sw 是存数 DataMemory[addr] = value。

## 第 6 章：IFU（取指令单元）——管理 PC，决定下一条指令在哪

### 6.1 功能

管理程序计数器（PC），实现"顺序执行"和"分支跳转"。

### 6.2 电路结构

```
       ┌──→ PC寄存器(32位) ──→ IM（取指令）
       │
Clock ─┤
       │
       └──→ Adder(PC+4) ──→ 下一条顺序地址
```

| 元件 | 说明 |
|------|------|
| **PC Register** | 32 位寄存器，存储当前指令地址 |
| **Adder** | 32 位加法器，计算 PC + 4 |
| **Constant 0x4** | 常量 4 |
| **IM** | 嵌套的指令存储器子电路 |
| Clock | 时钟信号 |

### 6.3 为什么是 PC+4？

- MIPS 指令定长 4 字节
- 下一条顺序指令地址 = 当前 PC + 4
- 如果是 `beq` 分支且条件成立，地址 = PC+4 + 偏移量×4

### 6.4 工作流程

1. 时钟上升沿到来
2. PC 寄存器输出当前值 → IM 取指令
3. 同时 Adder 计算 PC+4
4. 如果是分支指令且 Zero=1，选择分支地址；否则选 PC+4
5. 时钟下一个上升沿，PC 更新为新地址

> **注意**：IFU 是电路中**唯一涉及时钟的子模块**。PC 寄存器必须在时钟沿才能更新，这也是"单周期"的关键——每个周期取一条新指令。

## 第 7 章：ALUControl——生成 ALU 操作码

### 7.1 功能

根据主控制器发来的 3 位 ALUOp 和指令的 6 位 func 码，生成 3 位 ALU 控制码，决定 ALU 做什么运算。

### 7.2 输入→输出

| 指令 | ALUOp | func | → ALU动作 | ALU控制码 |
|------|:-----:|------|----------|:--------:|
| addu | 000 | 100001 | 加法 | 000 |
| subu | 000 | 100011 | 减法 | 001 |
| ori | 011 | — | 按位或 | 011 |
| lui | 010 | — | 移位 | 010 |
| lw/sw | 001 | — | 加法（算地址） | 000 |
| beq | 001 | — | 减法（比大小） | 001 |

### 7.3 实现方式：硬连线组合逻辑

ALUControl 是一个**纯组合逻辑电路**（没有寄存器、没有时钟）。实现方式是"与-或"阵列：

1. 用一个 **Splitter** 把 6 位 func 码拆成 6 根独立线
2. 用 **AND 门** 检测特定指令的 opcode+func 组合：
   - `addu` AND 门：9 个输入（3 位 ALUOp 的反相 + 6 位 func 的特定组合）
   - `subu` AND 门：同样 9 个输入
   - `ori` AND 门：3 个输入（匹配 ALUOp=011）
   - `lui` AND 门：3 个输入
   - `lw` AND 门：3 个输入
   - `sw` AND 门：3 个输入
   - `beq` AND 门：3 个输入
3. 用 **OR 门** 综合：多个指令可能对应同一 ALU 操作（如 addu 和 lw/sw 的地址计算都是加法）

### 7.4 怎么读懂这个电路

在 Logisim 中打开 ALUControl：

1. 左侧：`ALUop` 3 位输入 + `func` 6 位输入
2. 中间：多行 AND 门阵列，每个 AND 门标签标注了指令名（`addu`, `subu`, `ori`, `lui`, `lw`, `sw`, `beq`）
3. 右侧：多级 OR 门，把相同 ALU 动作的指令合并
4. 最右：3 位输出

> **核心思想**：每种指令的 AND 门都是"识别器"——只有当输入 pattern 完全匹配时输出 1。OR 门把需要相同 ALU 动作的指令"合并"在一起。

## 第 8 章：Controller（主控制器）——CPU 的大脑

### 8.1 功能

输入 6 位 opcode，输出 9 个控制信号，指挥所有其他模块协调工作。

### 8.2 输入和输出

**输入**：
- 6 位 opcode（指令的 [31:26]）

**输出（9 个控制信号）**：

| 信号 | 位宽 | 含义 |
|------|:---:|------|
| RegDst | 1 | 0=rt 是目的寄存器, 1=rd 是目的寄存器 |
| ALUSrc | 1 | 0=RD2 作为 ALU 输入B, 1=立即数作为 ALU 输入B |
| MemtoReg1 | 1 | 写回数据选择高位 |
| MemtoReg2 | 1 | 写回数据选择低位（和 MemtoReg1 组成 2 位） |
| RegWrite | 1 | 是否写寄存器 |
| MemRead | 1 | 是否读内存 |
| MemWrite | 1 | 是否写内存 |
| Branch | 1 | 是否分支跳转 |
| EXTOp | 1 | 0=零扩展, 1=符号扩展 |
| ALUOp0~2 | 3 | ALU 操作码（送给 ALUControl） |

### 8.3 实现方式

和 ALUControl 一样是硬连线组合逻辑，但规模更大：

1. **Splitter**：把 6 位 opcode 拆成 6 根线
2. **AND 门阵列**（每个指令一个）：
   - `R` AND 门（6 输入）：匹配 opcode=000000（R 型指令：addu、subu）
   - `lw` AND 门（6 输入）：匹配 opcode=100011
   - `sw` AND 门（6 输入）：匹配 opcode=101011
   - `beq` AND 门（6 输入）：匹配 opcode=000100
   - `ori` AND 门（6 输入）：匹配 opcode=001101
   - `lui` AND 门（6 输入）：匹配 opcode=001111
   - `nop` AND 门（6 输入）：匹配 opcode=000000 + func=000000（检测全 0 指令）
3. **OR 门**：综合各指令的控制信号
4. **NOT 门**：用于匹配 opcode 中的特定位（如 R 型 = 000000，需要 6 位全是 0，即每个位都取反后 AND）

### 8.4 看懂真值表的技巧

| 指令 | RegDst | ALUSrc | MemtoReg | RegWrite | MemRead | MemWrite | Branch | EXTOp |
|------|:------:|:------:|:--------:|:--------:|:-------:|:--------:|:------:|:-----:|
| addu | 1 | 0 | 00 | 1 | 0 | 0 | 0 | × |
| subu | 1 | 0 | 00 | 1 | 0 | 0 | 0 | × |
| ori | 0 | 1 | 00 | 1 | 0 | 0 | 0 | 0 |
| lw | 0 | 1 | 10 | 1 | 1 | 0 | 0 | 1 |
| sw | × | 1 | ×× | 0 | 0 | 1 | 0 | 1 |
| beq | × | 0 | ×× | 0 | 0 | 0 | 1 | 1 |
| lui | 0 | 1 | 01 | 1 | 0 | 0 | 0 | 0 |
| nop | 0 | 0 | 00 | 0 | 0 | 0 | 0 | 0 |

> × 表示不关心（0 或 1 都行），因为该指令不需要这个信号。

**对照着看**：
- **addu/subu**（R 型）：目的寄存器是 rd(RegDst=1)，ALU 的 B 端来自另一个寄存器(ALUSrc=0)，结果直接写回(RegWrite=1)
- **lw**：目的寄存器是 rt(RegDst=0)，ALU 的 B 端来自立即数(ALUSrc=1)，符号扩展(EXTOp=1)，写回来自内存(MemtoReg=10)，读写寄存器(RegWrite=1, MemRead=1)
- **sw**：ALU 算地址(ALUSrc=1)，符号扩展(EXTOp=1)，写内存(MemWrite=1)，不写寄存器(RegWrite=0)
- **beq**：比较寄存器(ALUSrc=0)，符号扩展(EXTOp=1)，分支使能(Branch=1)，不写回(RegWrite=0)

## 第 9 章：ALU（算术逻辑单元）——CPU 的计算核心

### 9.1 功能

执行所有算术和逻辑运算。本电路支持：加法（addu/lw/sw）、减法（subu/beq）、按位或（ori）、移位（lui）。

### 9.2 电路结构

```
输入A(32位) ──────→┐
                   ├──→ 4bitalu×8（或32位ALU内部逻辑）──→ 输出Result(32位)
输入B(32位) ──────→│                                    └→ Zero标志
                   │
ALU控制码(3位) ───→┘
```

### 9.3 层次化设计：4bitalu 是关键

参考电路中 ALU 内部嵌套了 `4bitalu`，即 4 位 ALU。整体思路：

```
1位ALU ─→ 级联4个 ─→ 4bitalu ─→ 级联8个 ─→ 32位ALU
```

**1 位 ALU 支持 4 种运算**：
- AND（与）
- OR（或）
- ADD（加法，带进位）
- SUB（减法 = 加补码）

通过多路选择器（MUX），根据控制码选择哪种运算结果输出。

### 9.4 进位链

级联时，低位的进位输出（CarryOut）连到高位的进位输入（CarryIn）：

```
ALU0(最低位, CarryIn=0) → ALU1 → ALU2 → ... → ALU31(最高位)
```

### 9.5 Zero 标志

所有 32 位结果经过一个 **NOR 门**（或等价的 OR+NOT）：只有当 32 位结果全是 0 时，Zero = 1。beq 指令用它判断两个寄存器是否相等。

> **关键**：beq $a, $b, offset 的实现 = `$a - $b` 用减法算，结果 = 0 则 Zero=1，触发分支跳转。

## 第 10 章：GRF（通用寄存器组）——32个32位寄存器

### 10.1 功能

提供 32 个通用寄存器，支持同时读 2 个 + 写 1 个（三端口）。

### 10.2 端口

| 端口 | 位宽 | 方向 | 说明 |
|------|:---:|:----:|------|
| `rs` 地址 | 5 | 输入 | 选择读端口1的寄存器（指令 [25:21]） |
| `rt` 地址 | 5 | 输入 | 选择读端口2的寄存器（指令 [20:16]） |
| `rd/rt` 写地址 | 5 | 输入 | 选择写入目标寄存器（RegDst MUX 选择） |
| 写数据 WD | 32 | 输入 | 要写入的数据 |
| RegWrite | 1 | 输入 | 写使能 |
| CLK | 1 | 输入 | 时钟 |
| RD1 | 32 | 输出 | 读数据1（rs 的值） |
| RD2 | 32 | 输出 | 读数据2（rt 的值） |

### 10.3 实现方式

Logisim 中 GRF 通常用 **Register** 元件阵列（32 个 32 位寄存器）+ 地址译码器 + 多路选择器实现：

1. **5-32 译码器**：把 5 位地址翻译成 32 个寄存器中选哪一个
2. **32 个 Register 元件**：每个 32 位宽
3. **MUX**：根据 rs/rt 地址选择输出哪个寄存器的值
4. **$0 寄存器硬接线为 0**：数据输入端通过 AND 门控制，当地址为 0 时强制写入 0

> **重要设计点**：MIPS 规定 `$zero`（寄存器 0）恒为 0。无论你怎么往 $0 写，读出来永远是 0。这通常通过忽略对 reg[0] 的写入来实现。

## 第 11 章：main（顶层电路）——把所有模块连起来

### 11.1 整体结构

main 电路就是把前面所有子电路用**连线 + Tunnel + MUX** 连接成一个完整的处理器。

### 11.2 数据通路追踪（跟着一条指令走）

以 `lw $t0, 4($s0)` 为例，追踪数据流：

```
① 取指：PC → IM → 指令字 0x8E080004
② 译码：Splitter 拆分指令字
        → opcode=100011 → Controller → 控制信号
        → rs=10000($s0) → GRF RD1 → 读出 $s0 的值
        → rt=01000($t0) → 暂不用于读（regDst=0）
        → imm=0x0004 → EXT 符号扩展 → 0x00000004
③ 执行：ALU A = $s0的值
         ALU B = 0x00000004(ALUSrc=1,选立即数)
         ALU 做加法(ALUOp=001) → 得到内存地址
④ 访存：DM[A=ALU结果] → 读出内存数据(MemRead=1)
⑤ 写回：MemtoReg MUX选内存数据 → GRF WD
         写地址=rt(RegDst=0) → GRF A3
         RegWrite=1 → 写入 $t0
```

### 11.3 如何追踪连线

在 Logisim 中，**Tunnel**（隧道）是关键线索。Tunnel 是一种"无线连接"——同名的 Tunnel 自动连通。例如：

- 名为 `RegWrite` 的 Tunnel：Controller 输出 → 同时连到 GRF、DM、各 MUX
- 名为 `Instr` 的 Tunnel：IM 输出 → 连到 Controller 和 Splitter
- 名为 `RegData` 的 Tunnel：写回数据总线

看 main 电路的方法：
1. 先找到所有 Tunnel 标签，理解信号名称的含义
2. 从 PC 出发，沿着数据线逐段追踪
3. 关注每个 MUX —— 它决定了数据走哪条路

### 11.4 关键 MUX 和数据选择

| MUX | 选择什么 | 控制信号 |
|-----|---------|---------|
| PCSrc MUX | PC+4 还是 分支地址 | Branch & Zero |
| RegDst MUX | 写 rt 还是 rd | RegDst |
| ALUSrc MUX | RD2 还是 立即数 | ALUSrc |
| MemtoReg MUX | ALU结果/移位/内存 | MemtoReg1, MemtoReg2 |

## 第 12 章：总结——怎么向老师解释这套电路

### 12.1 整体架构一句话

> 这是一个**单周期 MIPS 处理器**，所有指令在一个时钟周期内完成取指、译码、执行、访存、写回五个阶段。采用**模块化层次化设计**，共 13 个子模块，通过**硬连线控制**（组合逻辑）产生控制信号。

### 12.2 各模块一句话解释

| 模块 | 一句话 |
|------|--------|
| IFU | PC寄存器 + 加法器，管理取指地址 |
| IM | ROM，存机器码 |
| Controller | 组合逻辑，opcode → 9 个控制信号 |
| ALUControl | 组合逻辑，ALUOp+func → ALU操作码 |
| GRF | 32×32 寄存器，三端口，$0 恒为零 |
| EXT | 16→32 位符号扩展 |
| Zero_EXT | 16→32 位零扩展 |
| Shift | 左移 2 位（×4），用于分支地址 |
| ALU | 加法/减法/按位或/移位，输出 Zero 标志 |
| DM | RAM，lw 读 sw 写 |
| main | 顶层连线，MUX 完成数据路径选择 |

### 12.3 8 条指令如何支持

| 指令 | 本质在做什么 |
|------|-------------|
| addu | R[rd] = R[rs] + R[rt]（寄存器+寄存器） |
| subu | R[rd] = R[rs] - R[rt] |
| ori | R[rt] = R[rs] \| 零扩展(imm) |
| lw | R[rt] = MEM[R[rs] + 符号扩展(imm)] |
| sw | MEM[R[rs] + 符号扩展(imm)] = R[rt] |
| beq | 如果 R[rs]==R[rt], PC 跳转 |
| lui | R[rt] = imm << 16 |
| nop | 什么也不做（控制信号全 0） |
