# 指令集实现详解——每条指令如何在电路中执行

---

## 预备知识：MIPS 指令的三种格式

在理解每条指令之前，先要知道 32 位机器码怎么"拆"：

```
R型（寄存器型）：addu, subu
┌────────┬──────┬──────┬──────┬──────┬──────────┐
│ opcode │  rs  │  rt  │  rd  │ shamt│   func   │
│  6位   │ 5位  │ 5位  │ 5位  │ 5位  │   6位    │
└────────┴──────┴──────┴──────┴──────┴──────────┘
 31   26 25   21 20   16 15   11 10    6 5       0

I型（立即数型）：ori, lw, sw, beq, lui
┌────────┬──────┬──────┬─────────────────────────┐
│ opcode │  rs  │  rt  │      immediate(16位)     │
│  6位   │ 5位  │ 5位  │          16位            │
└────────┴──────┴──────┴─────────────────────────┘
 31   26 25   21 20   16 15                        0
```

**关键区别**：
- R 型：两个源寄存器(rs, rt) + 一个目的寄存器(rd) + 功能码(func)
- I 型：一个源寄存器(rs) + 一个目的寄存器(rt) + 16 位立即数

---

## 第 1 条：addu — 无符号加法（R型）

**指令格式**：`addu $rd, $rs, $rt`
**含义**：$rd = $rs + $rt
**机器码示例**：`addu $t1, $t0, $t2` = `0x010A4821`

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码 0x010A4821
  PC+4 加法器 ──→ 下一条地址（顺序执行）

② 译码
  机器码 → Splitter 拆成：
    opcode[31:26] = 000000  ──→ Controller
    rs[25:21]     = 01000   ──→ GRF 读地址1（$t0）
    rt[20:16]     = 01010   ──→ GRF 读地址2（$t2）
    rd[15:11]     = 01001   ──→ RegDst MUX（选rd = $t1）
    func[5:0]     = 100001  ──→ ALUControl

  Controller 输出：
    RegDst   = 1     ← 选 rd 作为目的寄存器
    ALUSrc   = 0     ← ALU 的 B 输入来自 RD2（寄存器值）
    MemtoReg = 00    ← 写回数据来自 ALU 结果
    RegWrite = 1     ← 需要写回寄存器
    MemRead  = 0     ← 不读内存
    MemWrite = 0     ← 不写内存
    Branch   = 0     ← 不分支
    EXTOp    = ×     ← 用不到
    ALUOp    = 000   ← 告诉 ALUControl：这是 R 型指令

  GRF：
    RD1 = $t0 的值（rs 读出）
    RD2 = $t2 的值（rt 读出）

③ 执行
  ALUControl 收到 ALUOp=000 和 func=100001：
    → 匹配 addu 的 AND 门
    → 输出 ALU操作码 = 000（加法）

  ALU：
    输入 A = $t0 的值（RD1，直接连过来）
    输入 B = $t2 的值（ALUSrc=0，选 RD2 那路）
    执行加法：A + B
    Zero = 0（几乎不会碰巧等于0）

④ 访存
  DM：MemRead=0, MemWrite=0 → 不做任何操作

⑤ 写回
  MemtoReg MUX（00 选 ALU 结果）：
    写数据 = ALU 加法结果
  写地址 = rd（RegDst=1，选 rd=01001=$t1）
  RegWrite=1 → 时钟上升沿，写入 $t1
```

### 一句话总结

> opcode=000000 让 Controller 知道这是 R 型指令 → ALUSrc=0 选寄存器做 ALU 输入 → ALU 做加法 → RegDst=1 选 rd → 结果写回 rd。

---

## 第 2 条：subu — 无符号减法（R型）

**指令格式**：`subu $rd, $rs, $rt`
**含义**：$rd = $rs - $rt
**机器码示例**：`subu $t1, $t0, $t2` = `0x010A4823`

### subu 和 addu 的唯一区别：func 码不同，其他全部相同

| 对比项 | addu | subu |
|--------|:----:|:----:|
| opcode | 000000 | 000000 |
| func   | **100001** | **100011** |
| Controller 输出 | 完全相同 | 完全相同 |
| ALUControl 输出 | **000（加）** | **001（减）** |
| 数据通路 | 完全一样 | 完全一样 |

### 区别在哪里起作用

```
Controller 无法区分 addu 和 subu！
因为它们的 opcode 都是 000000（R 型指令的标志）

区分工作交给了 ALUControl：
  func=100001 → addu AND 门匹配 → ALU 做加法
  func=100011 → subu AND 门匹配 → ALU 做减法

这就是"两级译码"的意义：
  Controller 负责大方向（R型还是I型）
  ALUControl 负责细节（具体做哪种运算）
```

### 数据通路（几乎同 addu）

```
① 取指：PC → IM → 机器码
② 译码：opcode=000000 → Controller 输出控制信号（同 addu）
          func=100011  → ALUControl 匹配 subu AND 门
③ 执行：ALU A - ALU B（减法！只有这里不同）
④ 访存：不操作
⑤ 写回：ALU结果 → rd
```

### 一句话总结

> subu 和 addu 几乎一模一样——唯一区别是 func 码不同，导致 ALUControl 让 ALU 做减法而不是加法。

## 第 3 条：ori — 或立即数（I型）

**指令格式**：`ori $rt, $rs, imm`
**含义**：$rt = $rs | zero_extend(imm)
**机器码示例**：`ori $t0, $zero, 0x006F` = `0x3408006F`

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码 0x3408006F

② 译码
  机器码 → Splitter 拆成：
    opcode[31:26] = 001101  ──→ Controller
    rs[25:21]     = 00000   ──→ GRF 读地址1（$zero）
    rt[20:16]     = 01000   ──→ GRF 读地址2 / 同时也作为目的寄存器
    imm[15:0]     = 0x006F  ──→ Zero_EXT（零扩展）

  Controller 输出：
    RegDst   = 0     ← 选 rt 作为目的寄存器（不是 rd！）
    ALUSrc   = 1     ← ALU 的 B 输入来自立即数（不是寄存器！）
    MemtoReg = 00    ← 写回数据来自 ALU 结果
    RegWrite = 1     ← 需要写回
    MemRead  = 0
    MemWrite = 0
    Branch   = 0
    EXTOp    = 0     ← 零扩展！（ori 是逻辑运算，无符号）
    ALUOp    = 011   ← 告诉 ALUControl：做 OR 运算

  GRF：
    RD1 = $zero 的值 = 0x00000000

  Zero_EXT：
    输入 imm = 0x006F(16位)
    输出 = 0x0000006F(32位，高位补0)

③ 执行
  ALUControl 收到 ALUOp=011：
    → 匹配 ori 的 AND 门
    → 输出 ALU操作码 = 011（按位 OR）

  ALU：
    输入 A = $zero 的值 = 0x00000000
    输入 B = Zero_EXT(0x006F) = 0x0000006F（ALUSrc=1，选立即数）
    执行按位或：0x00000000 | 0x0000006F = 0x0000006F

④ 访存：不做任何操作

⑤ 写回
  MemtoReg MUX（00，选 ALU 结果）= 0x0000006F
  写地址 = rt（RegDst=0！）= 01000 = $t0
  RegWrite=1 → 写入 $t0 = 0x0000006F（= 十进制 111）
```

### ori 和 R 型指令的关键区别

| 对比项 | addu/subu (R型) | ori (I型) |
|--------|:---:|:---:|
| 目的寄存器 | **rd** (RegDst=1) | **rt** (RegDst=0) |
| ALU B 来源 | **RD2** (ALUSrc=0) | **立即数** (ALUSrc=1) |
| 扩展方式 | 不需要 | **零扩展** (EXTOp=0) |
| ALU 操作 | 加法/减法 | **按位或** |

### 一句话总结

> ori 是 I 型指令：目的寄存器是 rt（不是 rd）→ 立即数零扩展后和寄存器做按位或 → 结果写回 rt。EXTOp=0 表示零扩展，因为 OR 是逻辑运算，不需要符号。

## 第 4 条：lw — 从内存加载字（I型）

**指令格式**：`lw $rt, imm($rs)`
**含义**：$rt = Memory[$rs + sign_extend(imm)]
**机器码示例**：`lw $t0, 4($t1)` → opcode=100011, rs=$t1, rt=$t0, imm=4

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码

② 译码
  机器码 → Splitter 拆成：
    opcode[31:26] = 100011  ──→ Controller
    rs[25:21]     = t1      ──→ GRF 读地址1（基地址寄存器）
    rt[20:16]     = t0      ──→ 目的寄存器
    imm[15:0]     = 0x0004  ──→ EXT（符号扩展）

  Controller 输出：
    RegDst   = 0     ← 目的寄存器是 rt
    ALUSrc   = 1     ← ALU 的 B 来自立即数
    MemtoReg = 10    ← ★ 写回数据来自内存！（和前面都不同）
    RegWrite = 1     ← 需要写回寄存器
    MemRead  = 1     ← ★ 读内存！
    MemWrite = 0
    Branch   = 0
    EXTOp    = 1     ← ★ 符号扩展！（地址偏移有正负）
    ALUOp    = 001   ← 告诉 ALU 做加法（算地址）

  GRF：
    RD1 = $t1 的值（基地址）

  EXT（符号扩展）：
    输入 imm = 0x0004(16位)
    输出 = 0x00000004(32位)

③ 执行（算地址！）
  ALUControl 收到 ALUOp=001：
    → 匹配地址计算的 AND 门
    → 输出 ALU操作码 = 000（加法）

  ALU：
    输入 A = $t1 的值（基地址）
    输入 B = 0x00000004（偏移量，ALUSrc=1 选立即数）
    执行加法：基地址 + 偏移量 = 内存地址

④ 访存（★ lw 的核心步骤）
  DM：
    地址 = ALU 结果（刚才算出的内存地址）
    MemRead=1, MemWrite=0
    → RAM[地址] 的值被读出 → DM 的 RD 输出

⑤ 写回（★ 数据来自内存，不是 ALU）
  MemtoReg MUX = 10：
    → 选 DM 读出的数据（不是 ALU 结果！）
  写地址 = rt = $t0（RegDst=0）
  RegWrite=1 → 写入 $t0 = 内存中的数据
```

### lw 和 ori 虽然都是 I 型，但区别很大

| 对比项 | ori | lw |
|--------|:---:|:---:|
| ALU 做什么 | **按位或**（得到结果本身） | **加法**（算内存地址） |
| 扩展方式 | 零扩展 | **符号扩展** |
| 写回来源 | ALU 结果 | **内存数据** |
| MemRead  | 0 | **1** |
| MemtoReg | 00 | **10** |

### 一句话总结

> lw 分两步：先让 ALU 做"基地址+偏移量"算出内存地址（加法），然后从 DM 读出该地址的数据，最后将内存数据（而不是 ALU 结果）写回 rt。

---

## 第 5 条：sw — 存储字到内存（I型）

**指令格式**：`sw $rt, imm($rs)`
**含义**：Memory[$rs + sign_extend(imm)] = $rt
**机器码示例**：`sw $t0, 4($t1)` → opcode=101011, rs=$t1, rt=$t0, imm=4

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码

② 译码
  机器码 → Splitter 拆成：
    opcode[31:26] = 101011  ──→ Controller
    rs[25:21]     = t1      ──→ GRF 读地址1（基地址寄存器）
    rt[20:16]     = t0      ──→ GRF 读地址2（要存的数据！）
    imm[15:0]     = 4       ──→ EXT（符号扩展）

  Controller 输出：
    RegDst   = ×     ← sw 不写寄存器，用不到
    ALUSrc   = 1     ← ALU 的 B 来自立即数
    MemtoReg = ××    ← 不写回，用不到
    RegWrite = 0     ← ★ 不写寄存器！
    MemRead  = 0     ← 不读内存
    MemWrite = 1     ← ★ 写内存！
    Branch   = 0
    EXTOp    = 1     ← 符号扩展（算地址）
    ALUOp    = 001   ← 做加法（算地址）

  GRF：
    RD1 = $t1 的值（基地址，读地址1 = rs）
    RD2 = $t0 的值（★ 要存储的数据！rt 在这里是读地址2）

③ 执行（算地址，和 lw 完全一样）
  ALU：
    输入 A = $t1 的值（基地址）
    输入 B = 符号扩展(4) = 0x00000004
    做加法：基地址 + 偏移量 = 内存目标地址

④ 访存（★ sw 的核心步骤）
  DM：
    地址 = ALU 结果（目标内存地址）
    写数据 WD = RD2 = $t0 的值（★ 来自 GRF RD2）
    MemRead=0, MemWrite=1
    → $t0 的值被写入 RAM[地址]

⑤ 写回
  无！RegWrite=0 → GRF 不写入任何东西
```

### sw 和 lw 对比——镜像操作

| 对比项 | lw | sw |
|--------|:---:|:---:|
| 数据方向 | 内存 → 寄存器 | 寄存器 → 内存 |
| MemRead | **1** | 0 |
| MemWrite | 0 | **1** |
| RegWrite | **1** | **0** |
| rt 的含义 | **目的寄存器**（写入目标） | **源寄存器**（读出数据） |
| 地址计算 | 基地址+偏移（一样） | 基地址+偏移（一样） |

### 一句话总结

> sw 和 lw 镜像对称：地址计算完全一样（基地址+偏移），但 lw 是从内存读出写回 rt，sw 是从 rt 读出写入内存。RegWrite=0, MemWrite=1。

## 第 6 条：beq — 相等则分支（I型）

**指令格式**：`beq $rs, $rt, label`
**含义**：如果 $rs == $rt，则 PC = PC+4 + sign_extend(imm)×4
**机器码示例**：`beq $t0, $t1, loop` → opcode=000100, rs=$t0, rt=$t1, imm=偏移量

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码
  同时：Adder 算出 PC+4

② 译码
  机器码 → Splitter：
    opcode[31:26] = 000100  ──→ Controller
    rs[25:21]     = t0      ──→ GRF 读地址1
    rt[20:16]     = t1      ──→ GRF 读地址2
    imm[15:0]     = offset  ──→ EXT（符号扩展）

  Controller 输出：
    RegDst   = ×     ← beq 不写寄存器
    ALUSrc   = 0     ← ★ ALU 的 B 来自 RD2（比较两个寄存器！）
    MemtoReg = ××
    RegWrite = 0     ← 不写寄存器
    MemRead  = 0
    MemWrite = 0
    Branch   = 1     ← ★ 允许分支！
    EXTOp    = 1     ← 符号扩展（分支偏移）
    ALUOp    = 001   ← 做减法（比较两数是否相等）

  GRF：
    RD1 = $t0 的值
    RD2 = $t1 的值

  EXT（符号扩展）：
    imm → 符号扩展 → 32位偏移量

  Shift（左移2位）：
    32位偏移量 → 左移2位 = 偏移量×4 = 字节偏移

  分支地址计算：
    Adder: (PC+4) + 偏移量×4 → 分支目标地址

③ 执行（★ 用减法判断相等）
  ALUControl 收到 ALUOp=001：
    → 匹配 beq/lw/sw 的地址/比较逻辑
    → 输出 ALU操作码 = 001（减法）

  ALU：
    输入 A = $t0（RD1）
    输入 B = $t1（RD2，ALUSrc=0 选 RD2）
    执行减法：$t0 - $t1
    如果 $t0 == $t1 → ALU 结果 = 0 → ★ Zero = 1
    如果 $t0 != $t1 → ALU 结果 != 0 → ★ Zero = 0

④ 决定跳转
  PCSrc = Branch AND Zero
    ┌─────────────────────────────────┐
    │ Branch 来自 Controller = 1      │
    │ Zero 来自 ALU                  │
    │ AND 门输出 = PCSrc             │
    └─────────────────────────────────┘

  如果 $t0 == $t1：Zero=1 → PCSrc=1 → 选分支地址 → 下周期 PC 跳转
  如果 $t0 != $t1：Zero=0 → PCSrc=0 → 选 PC+4   → 下周期顺序执行

  PCSrc MUX：
    0 路：PC+4（顺序执行）
    1 路：PC+4 + 偏移量×4（跳转目标）
    选择端：Branch & Zero

⑤ 写回
  无！beq 不写寄存器、不访存
```

### 为什么用减法来比较相等？

```
不需要额外的"比较器"电路。ALU 做减法：
  $t0 - $t1 = 0  ←→  $t0 = $t1
  $t0 - $t1 ≠ 0  ←→  $t0 ≠ $t1

Zero 标志直接告诉你结果：
  Zero=1 → 两数相等
  Zero=0 → 两数不等
```

### 为什么偏移量要 ×4？

```
MIPS 指令定长 4 字节，所有指令地址都是 4 的倍数。
偏移量 field 存储的是"指令条数"，不是"字节数"。

例如：beq 向后跳 3 条指令：
  imm = 3  → 符号扩展 → 左移2位 → 12 → PC+4+12 → 正确地址
```

### 一句话总结

> beq 让 ALU 做减法比较两个寄存器 → Zero=1 说明相等 → Branch & Zero = 1 → PCSrc MUX 选分支地址 → 下一条指令从目标地址取。偏移量要经符号扩展后再×4。

## 第 7 条：lui — 加载高位立即数（I型）

**指令格式**：`lui $rt, imm`
**含义**：$rt = imm << 16（高 16 位 = imm，低 16 位 = 0）
**机器码示例**：`lui $t0, 0x1234` → opcode=001111, rt=$t0, imm=0x1234
**结果**：$t0 = `0x12340000`

### 数据通路追踪

```
① 取指
  PC ──→ IM ──→ 机器码

② 译码
  机器码 → Splitter：
    opcode[31:26] = 001111  ──→ Controller
    rt[20:16]     = t0      ──→ 目的寄存器
    imm[15:0]     = 0x1234  ──→ Zero_EXT（零扩展）

  Controller 输出：
    RegDst   = 0     ← 目的寄存器是 rt
    ALUSrc   = 1     ← ALU 的 B 来自立即数（扩展后）
    MemtoReg = 01    ← ★ 写回数据来自 Shift 模块！（不是 ALU，不是内存）
    RegWrite = 1     ← 需要写回
    MemRead  = 0
    MemWrite = 0
    Branch   = 0
    EXTOp    = 0     ← 零扩展
    ALUOp    = 010   ← 告诉 ALUControl：这是 lui（需特殊处理）

③ 执行（lui 的特殊路径）
  Zero_EXT：
    输入 imm = 0x1234(16位)
    输出 = 0x00001234(32位，零扩展)

  Shift：
    输入 = 0x00001234
    输出 = 0x00001234 << 16 = 0x12340000
    （注意：Shift 模块在 beq 里是用来左移2位的，
      但在这里它配合 lui 的路径实现左移16位。
      实际上是通过 Splitter 重新排列数据线来实现的）

  ALU：
    此时 ALU 也在工作，但它的结果不会被使用。
    因为 MemtoReg=01，写回路径选的是 Shift 输出，不是 ALU 输出。

④ 访存：不做任何操作

⑤ 写回
  MemtoReg MUX = 01：
    → 选 Shift 模块的输出（0x12340000）
    → ★ 不走 ALU，也不走 DM
  写地址 = rt = $t0（RegDst=0）
  RegWrite=1 → 写入 $t0 = 0x12340000
```

### lui 的独特之处

```
lui 是唯一一个 MemtoReg=01 的指令！

MemtoReg 的含义：
  00 → 写回数据 = ALU 结果（addu/subu/ori）
  01 → 写回数据 = Shift 输出（lui）     ← 特殊路径！
  10 → 写回数据 = DM 数据（lw）

为什么需要特殊路径？
  MIPS 立即数只有 16 位，无法一次加载 32 位常数。
  lui 负责填高 16 位，ori 负责填低 16 位。

  加载 0x1234ABCD 到 $t0：
    lui $t0, 0x1234    → $t0 = 0x12340000
    ori $t0, $t0, 0xABCD → $t0 = 0x1234ABCD
```

### 一句话总结

> lui 把 16 位立即数零扩展后左移 16 位，通过专门的写回路径（MemtoReg=01）直接送到 GRF 写端口。它和 ori 配合可以加载任意 32 位常数。

## 第 8 条：nop — 空指令

**指令格式**：`nop`
**机器码**：`0x00000000`（全 0）
**含义**：什么也不做，占用一个时钟周期

### 为什么 nop 天然等于"什么也不做"

```
nop 机器码 = 0x00000000

拆解：
  opcode = 000000  → Controller 按 R 型指令处理
  rs = 00000       → GRF 读地址1 = $zero
  rt = 00000       → GRF 读地址2 = $zero
  rd = 00000       → 写目标 = $zero
  shamt = 00000
  func = 000000

Controller 输出：
  RegDst   = 1    ← 选 rd = $zero
  ALUSrc   = 0
  MemtoReg = 00
  RegWrite = 0    ← ★ nop 的 AND 门让 RegWrite=0！（关键！）
  MemRead  = 0
  MemWrite = 0
  Branch   = 0
  ALUOp    = 000

关键：
  虽然 opcode=000000 被 Controller 中"R" AND 门匹配，
  但 func=000000 也被 Controller 中"nop" AND 门匹配。

  nop AND 门的作用：压制 RegWrite 信号，让它等于 0。

  所以即使其他控制信号按 R 型输出，因为 RegWrite=0：
    尝试把 ALU($zero + $zero = 0) 写回 $zero
    → 但 RegWrite=0 写不进去
    → 而且 $zero 本来就是 0，即使写进去也没影响

  而且 Branch=0, MemWrite=0, MemRead=0
  → 内存不动、PC 顺序走、寄存器不动
  → 完美空转！
```

### nop 的硬件实现

在 Controller 中有一个专门的 AND 门，标签 `nop`：

```
nop AND 门的检测条件：
  opcode = 000000（6个0）
  func   = 000000（6个0）

当这 12 位全是 0 时，nop AND 门输出 1，
对应的 OR 门把 RegWrite 强制拉到 0。
```

### nop 有什么用

```
1. 流水线填充（单周期不需要，但了解下）
2. 延迟槽填充（分支后空转）
3. 指令对齐（保证特定指令在特定地址）
4. 精确延时（每个 nop 占一个周期）
```

### 一句话总结

> nop 的机器码全 0，Controller 中专门的 nop AND 门检测 func=000000，强制把 RegWrite=0，让 CPU 在一周期内不做任何有效操作（不写寄存器、不写内存、不分支），只让 PC+4 往前走。

## 结语：理解这 8 条指令就够了

一旦你彻底理解这 8 条指令的数据通路，后续任何 MIPS 指令的学习方法完全一样：

1. 看指令格式（R 型还是 I 型）
2. 明确数据从哪来（rs, rt, 立即数, 内存）
3. 数据到哪去（rd, rt, 内存）
4. ALU 做什么运算
5. 推导 9 个控制信号的值

**本质上 CPU 就是一个"数据路由器"——控制信号决定了数据走哪条路。**
